# Google Play Data Safety draft

Use this as a review worksheet; answer the live Play Console form according to the production build and deployed backend.

## Security practices

- Data encrypted in transit: Yes (HTTPS/TLS and WhatsApp transport)
- Users can request deletion: Yes, through support email; temporary media also expires automatically
- Account creation: No account
- Independent security review: No, unless one is completed before submission

## Data collected by the StatusDrop service

### Photos and videos

- Data: finished MP4 clips generated by the Android app
- Collected: Yes; required for WhatsApp delivery
- Shared: Conservatively declare Yes if Play treats WhatsApp/Meta delivery as third-party sharing; Cloudflare/Azure act as service providers
- Purpose: App functionality
- Processing: Uploaded only after local compression; originals selected in the app are not uploaded
- Retention: Temporary, stage-based; see privacy policy

### Files and docs metadata

- Data: clip filename, order, byte size, duration, selected quality profile, SHA-256 integrity hash
- Collected: Yes
- Purpose: App functionality, fraud prevention/security, integrity verification
- Retention: Temporary upload session data

### Device or other identifiers / network data

- Data: IP address and ordinary request/security information
- Collected: Yes
- Purpose: Security, abuse prevention, rate limiting, diagnostics

### User identifiers used for delivery

- Data: WhatsApp sender identifier and activation-message/code after the user leaves the app and initiates WhatsApp delivery
- Collected: Yes by the StatusDrop delivery service
- Shared: WhatsApp/Meta necessarily processes the sender and delivered media
- Purpose: App functionality
- Retention: Temporary delivery/retry session and provider operational logs

### Support information

- Data: email address, Instagram identity, and support-message content only when the user voluntarily contacts support
- Collected: Optional
- Purpose: Developer communications/support

## Data not collected by the Android app

- Precise or approximate location
- Contacts/address book
- Advertising ID
- Financial/payment data
- Health data
- Browsing history
- Search history
- Installed-app inventory
- Audio recordings
- Analytics or advertising events

## Important review items

1. Verify whether Play classifies user-initiated WhatsApp delivery as “sharing” in the current form; use the conservative answer if uncertain.
2. Ensure the deployed privacy policy exactly matches production retention and deletion behavior.
3. Ensure Ko-fi/donation links are absent from the Play build.
4. Ensure no analytics/ad SDK has been added since this document was written.
5. Recheck every Maven/Flutter dependency before each release.
